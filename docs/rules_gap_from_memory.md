## 2. メモリにのみあるルール — チーム共通(CLAUDE.md)候補

### 2-1. 不具合は再現してから直す

- **ルール**: バグ報告への原因説明・修正は、最小再現(実物ファイルがあればそれ)で
  同じ現象を確定させてから行う。修正後も同じ実物で before/after を確認する。
  誤った原因説明を文書に書いてしまった場合は、事実確定後に訂正の追記を残す。
- **経緯**: もっともらしい仮説での修正・説明を2回続けて外し(2026-08-01、null エラーの
  誤診)、「推測をせず実態に基づいた実装、修正を施せ」と明確な指摘を受けた。

### 2-2. ファイル変換・複製は元の形式を保存する

- **ルール**: ファイルを複製・加工して書き出す機能では、出力形式を自分で決め直さず、
  入力の形式(ヘッダの有無・列構成・値の表記)を保って必要なセルだけ書き換える。
  形式のパース処理は読む側・書く側で1箇所に共有する(別々に前提を持たない)。
- **経緯**: ダミー展開が initial_temperature を「読める正規形」へ変換して列を黙って
  落とすバグ(2026-08-03、ver.0.7.3 で修正)。

### 2-3. 呼称・表記

- チーム環境の呼称は「社内」ではなく**「チーム内」「チームコンテナ」**と書く
  (コード内コメント・ドキュメント共通。2026-08-05 指示)。

## 3. メモリにのみあるルール — プロジェクト専用(.claude/rules/scorelib_param.md)候補

### 3-1. push・タグ付け前チェックは4点セット

- **ルール**: push 前(特にリリース・タグ付け前)に pytest 全件 / `ruff check .`
  (素と `--preview` の両方) / **`ruff format --check .`** / pyright の4点を全部回す。
  pre-push フックが担保するのは pytest だけ。タグは CI が緑になったコミットに付ける。
  コードは「行長 119 に収まるなら折り返さない」(ruff format が1行に畳むため)。
- **経緯**: ver.0.7.2 リリース時に format 検査だけ漏らして CI を落とし、タグを付け直した
  (2026-08-03)。個々のコマンドは README に記載があるが「タグ前に4点全部」という
  チェックリストの形ではどこにも書かれていない。

### 3-2. リリース実績ゼロの間は互換コードを書かない

- **ルール**: このリポジトリはまだ誰にも配布実績がない(ver タグはあるが SVN 同期
  未実施。2026-08-02 確認)。廃止・改名では移行コード・案内エラー・「旧: 〜」注記を
  書かず**黙って消す**。互換層を提案する前に「その表記は実験側(SVN / 実験 config)に
  実在したか」を確認する。
- **付随の表記ルール**: ユーザーに見せる可能性のある文書(README・UI 文言)には、
  存在しないものへの言及(「旧〜は廃止」「従来どおり」等)を置かない。設計書・
  進捗記録には過去の記録があってよい。
- **用語の正**: 実験側の正式形式は WLgroup 系キー(WLgroup / WLgroupDefinLogical /
  WLgroupWeight)。groupDefs / weightSets は任意軸への一般化のための内部の入れ物で
  あり「旧形式/新形式」という呼び方は誤り。
- **注意**: 初回リリース(SVN 同期)後はこの前提が失効するので、その時点でルールを更新する。

### 3-3. エンジンのリリースは先送りしない

- **ルール**: エンジン変更が main に載って CI が緑になったら、その場でリリース
  (CHANGELOG 確定 → `__version__` → コミット → ver タグ → push --follow-tags)まで
  進める。「次のリリースのタイミングで」と保留しない(2026-08-01 の明示指示:
  「普通は常にいつでもバージョンアップできる」。実行前の確認は不要)。
- **⚠ 統合時に要整理**: 旧 AGENTS.md 環境メモの「コミット・push・タグ付けは
  ユーザーの指示があるときだけ行う」と衝突する。時系列では 3-3 が後の指示だが、
  適用範囲(リリース作業に限るのか)を統合時にユーザーへ確認して一本化すること。

### 3-4. ruff 免除リストにはルールの意味を併記する

- **ルール**: ruff の免除(ignore)リストには、ルールコードだけでなく
  「何を禁止するルールか」の意味を必ず併記する(2026-08-05 指示)。

### 3-5. ユーザー私物ファイルはコミットしない

- **ルール**: リポジトリ直下に置かれるバグ再現用の実ファイル
  (`config_*_test.jsonc`・`result_tmp_dummy.zip` 等)はユーザーの私物で、実データを
  含むためコミット禁止。.gitignore のコメントにはあるがルール文書には未記載。
